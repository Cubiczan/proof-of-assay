An audit agent pattern for mining payables: assay certificates and supplier
invoices are reconciled lot by lot, exceptions are priced as cash at risk,
and every decision is written into a SHA-256 hash chain that anyone can
re-verify. On 2026-10-18 the open-weight model (Qwen2.5-1.5B-Instruct via
vLLM, pinned image `vllm/vllm-openai:v0.10.2`) was served live on a Nosana
RTX 3090 deployment and stopped after the run, and the verified receipt
bundle was anchored on Arweave via the Turbo free tier. The audit +
verification layer remains fully reproducible locally without a GPU.

Oct 31, 2026). Entry is a HackerNoon article — see `ARTICLE.md` (ready for

## How verification works

`expected = tonnes x contracted_price`; variance, grade and quantity
mismatches flag exceptions (see `proof_of_assay/audit.py`). Each decision
becomes a hash-chain entry: `sha256(prev_hash | index | type | canonical_payload)`.
Changing any payload breaks `verify_chain` — the Streamlit app demos this
live (tamper toggle -> FAIL).

## Runs on Nosana

The audit verdicts are decided by deterministic rules, not by the model. A Nosana
GPU is used only to serve an open-weight Qwen model that *explains* already-flagged
exceptions. The 2026-10-18 live run served Qwen2.5-1.5B-Instruct via vLLM and is
stopped; that model's one test answer was wrong. The job below upgrades the
narration layer to a 4-bit `qwen2.5:7b` instruct model via Ollama, with an
OpenAI-compatible endpoint.

Do not start this deployment with the wallet / NOS+SOL CLI path. Pay with account
credits from the dashboard (or an API key). Use **Simple** strategy, **1 replica**,
a **60-minute** container timeout, and stop the deployment when you are done.
Unused time is refunded.

### Job definition

See `nosana/proof-of-assay-llm.json`. A first job definition used a
`resources` entry of type `Ollama` to preload `qwen2.5:7b`. On the
2026-11-11 run the container came up healthy (`GET /api/tags` returned
200) but the model list was empty, and the model had to be pulled by
hand with `POST /api/pull`. Official Nosana resource types are S3 and
Hugging Face, not a first-class Ollama preload. The job now follows
[Nosana's documented Ollama pattern](https://learn.nosana.com/inference/endpoints):
start `ollama serve`, wait until `ollama list` succeeds, then
`ollama pull "$MODEL"`.

```json
{
  "version": "0.1",
  "type": "container",
  "ops": [
    {
      "id": "proof-of-assay-llm",
      "type": "container/run",
      "args": {
        "gpu": true,
        "image": "docker.io/ollama/ollama:0.32.6",
        "env": {
          "MODEL": "qwen2.5:7b"
        },
        "entrypoint": ["/bin/sh"],
        "cmd": [
          "-c",
          "ollama serve & pid=$!; i=0; until ollama list >/dev/null 2>&1 || [ \"$i\" -ge 60 ]; do i=$((i+1)); sleep 1; done; ollama pull \"$MODEL\"; wait $pid"
        ],
        "expose": [
          {
            "port": 11434,
            "health_checks": [
              {
                "type": "http",
                "path": "/api/tags",
                "method": "GET",
                "expected_status": 200,
                "continuous": false
              }
            ]
          }
        ]
      }
    }
  ],
  "meta": {
    "trigger": "dashboard",
    "system_requirements": {
      "vram_total_mb": 8192
    }
  }
}
```

The image pin (`ollama/ollama:0.32.6`) is the build currently pre-cached on the
recommended markets. Official Nosana Qwen templates pin `0.35.1`; switch only if
`0.32.6` cannot load the model. An official dashboard alternative is the **Qwen
3.5 9B** template (`qwen3.5:9b`, ~6.6 GB, also 4-bit via Ollama) if you want the
newer official catalog model on a 10 GB+ card.

### Dashboard (credits, no wallet)

1. Sign in at https://deploy.nosana.com with the account that holds the credits.
2. Open https://deploy.nosana.com/deployments/create
3. Name it e.g. `proof-of-assay-llm`.
4. Click **Configure**. Paste the job definition above (or import `nosana/proof-of-assay-llm.json`).
5. Select the **NVIDIA 4070** premium market (or 3090 if 4070 has no hosts).
6. Deployment strategy **Simple**, replica count **1**, container timeout **60 minutes**.
7. Create the deployment. Wait until the endpoint is healthy (`/api/tags` or `/v1/models`).
   First start can take a few minutes while the 4-bit model is fetched.
8. Copy the service URL. Call it as an OpenAI-compatible API, then **stop** the deployment.

```bash
export NOSANA_LLM_BASE_URL="https://<deployment-host>"   # /v1 is added if missing
# export NOSANA_LLM_API_KEY="..."   # only if the endpoint requires one
export NOSANA_LLM_MODEL="qwen2.5:7b"
python scripts/reproduce.py --explain
# optional: curl $NOSANA_LLM_BASE_URL/v1/chat/completions ...
```

When `NOSANA_LLM_BASE_URL` is unset, `reproduce.py` (with or without `--explain`)
and `proof_of_assay.llm` skip the network call and the fixture audit is unchanged.

## Honest limitations

- Data is synthetic; amounts are fixture arithmetic, not real mine documents.
- The LLM is not in the reproducibility path: rules decide, the model only
  explains/extracts. In its one live Nosana test the raw 1.5B model answered
  incorrectly (see `ARTICLE.md` / `live_evidence.json`), so it is not claimed
  to audit reliably alone. The 2026-11-11 7B run only narrated already-decided
  verdicts; those paragraphs are not hashed into the chain.
- The October 18 vLLM deployment is stopped. The November 11 Ollama
  deployment was started for a short demo (see `docs/nosana-demo.mp4`) and
  is not a standing public service — stop it when idle. The Arweave
  anchor is live: https://arweave.net/yTIbmFhgUS88RNaO2W92Oy7kPigpMyRUmToOeumLSus
